## 四、「颜色信号够不够清楚」自我评估

**结论：清楚，而且比改前清楚得多；但清楚的方式变了——从「颜色写在字面上」变成「行为落在轴上」。**

1. **col 与轴同向率 18/20 → 20/20。**
   按仓库自己的 color-pie 映射（`check_bank4.AXIS_COLORS`），新 20 个选项的轴全部蕴含它标注的颜色。
   改前有两处反向：s62C 标白却带 `drain/control`（黑蓝轴），s62A 标红却带 `grave/enchant`（黑绿轴）——
   即颜色加 14% 的分，轴却在 60% 的相似度上往反方向拉。现在两股力同向。

2. **纯色答题者的轴画像不再「一个轴打天下」。**
   | | 改前（四题全选该色） | 改后 |
   |---|---|---|
   | 绿 | `ramp 6.8 / counters 3.2` | `tribal 3.5 / counters 3.0 / ramp 3.0 / wide 3.0` |
   | 白 | `enchant 2.8 / control 1.7 / stax 1.4 / drain 1.3` | `stax 5.0 / politics 2.5 / wide 2.0` |
   | 红 | `aggro 2.2 / chaos 1.8 / grave 1.7 / enchant 1.4` | `aggro 6.0 / chaos 4.0 / spells 1.5 / voltron 1.5` |
   | 黑 | `stax 4.2 / grave 3.0` | `drain 5.0 / grave 3.5 / combo 1.5 / ramp 1.0 / stax 1.0` |
   | 蓝 | `artifacts 2.8 / control 2.8 / drain 1.9` | `control 6.5 / combo 2.0 / clonesteal 2.0 / artifacts 1.5` |

   改前 白/蓝/红 的画像里混着黑、绿轴的噪音，改后每个颜色只在自己的轴上累积。

3. **「四道题其实是一道题」被量化地消掉了。**
   四道题之间（不含同题内）两两余弦：改前 **10 组 ≥ 0.85，最大 1.000**（s49B蓝×s60B蓝、s60E绿×s62E绿、s59D白×s60D白 方向完全相同）；
   改后 **0 组 ≥ 0.85，最大 0.800**，平均 0.161 → 0.105。
   同色槽位的轴组合也从「三题都是 ramp/counters」变成四题四个样子：
   绿 = `tribal/counters`｜`enchant/counters/ramp`｜`wide/tribal`｜`ramp/wide/counters`。

4. **四个侧面的区分度。**
   题内最高余弦只有 0.327（s62 组织者 × 供养者），s60 题内是 0.000——五个选项各自指向互不重叠的轴组合，
   「五个选项吸引力均衡、没有明显正确答案」这一条守住了。

5. **仍然要说的三点保留意见：**
   - **stax 是白的中枢，不是位置套路。** 四道题的白选项里有 3 个带 stax（两个以它为主），因为「秩序/规矩」本来就是白的语义核心；但四题的白选项位置是 D/A/E/C 各不相同，第四个（s62 组织者）完全不带 stax，轴组合也四样不同。这是刻意保留的、语义上正确的收敛，不是毛病二的复发。
   - **余弦是尺度无关的，纯轴选项天然会与全库同轴选项同向。** 新选项与全库其它选项的最大余弦平均 0.949（min 0.816）——因为 20 轴的体系里，任何纯 `chaos` 选项都跟别的纯 `chaos` 选项同向。这是「同一特质在别的场景里也出现」，不是撞题；判定撞题要看题内区分度（≤0.327）与题间轴复用（18/20 轴被用到、无轴主导 ≥3 题，仅 stax 与 aggro 各 3 题）。
   - **s62 与既有社会题存在题材邻接**（s38「谁当领队」、h3c2「大群里的位置」、s78 多选「常当的角色」）。s62 换了场景（一起弄同一件事做了几周）与五个具体行为，文本零重叠，但它是四道新题里与旧题距离最近的一道，如果想更保守可以再换场景。
   - s49 D 的 `stax 1.5 + enchant 1.5` 是唯一的主轴并列，自检 6 里按 `enchant+stax` 记账。
