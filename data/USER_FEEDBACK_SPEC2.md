# 三条用户反馈的修改规范

用户实测反馈：三道题的**情景假设太窄**，有人对不上号。逐条改，**不要动其它题**。

## 硬性约束

- 每题选项数 3~7（本题库把上限从 6 放宽到 7，见 s50 的说明）
- 每选项 1~3 个玩法轴，权重 0.5~3.0
- 同题内两两轴向量余弦 < 0.85
- 选项文本不能出现万智牌术语
- 语气口语化，五个选项的吸引力要均衡

---

## 反馈1 · `s50`「周末晚上窝在沙发上，你会点开哪一类？（长片、短视频都算）」

现有 6 个选项（A 动作片 / B 推理悬疑 / C 群像剧 / D 黑帮片 /
E 连刷到凌晨 / F 动画番剧）。

**用户反馈**：希望能加**恐怖片**。

**处理**：加第 7 个选项（G）。⚠️ 需要同时把
`scripts/validate_questions.py` 里的选项上限从 6 改成 7，
并在 commit 说明里写清为什么放宽。

新选项要落在「享受紧张感 / 被吓到也爽」这个感觉上，
轴不要和现有 6 项撞（先算出新选项与现有各项的余弦，报出来）。

---

## 反馈2 · `s10`「点了外卖，显示还要四十分钟才到，这四十分钟你在？」

现有 5 个选项全绑在外卖这一个情景上（刷配送进度、敲门声）。

**用户反馈**：有的用户不点外卖，对不上号。

**处理**：把情景改成**更普遍但内核不变**的——

要测的内核是「**一段必须等的空白时间，你怎么过**」。
可以改成一个「等」的通用情景，也可以把题干写成覆盖几种常见等法的说法
（外卖、快递、等一个回话、等一个结果……任选一种自然的写法）。

**同时必须把选项里绑死外卖的措辞改掉**，例如：
- A「隔五分钟刷一次**配送进度**」→ 改成通用的「隔一会儿就去看一眼进度」
- D「压根忘了这事，**敲门声**一响才想起来点了外卖」→ 改成通用的触发方式
- C/E 提到冰箱的部分可以保留（冰箱是普遍的家居物件）

**不能改的**：这题在测的五档区分度（盯着等 / 拿去干别的 / 先自己应付一下 /
压根不惦记 / 顺手把等待变成一次整理），改完要保证这五档仍然分得开。

## 反馈3 · `s18`「公司要你三个月后搬去另一个城市。你从哪一步开始？」

现有 5 个选项（问熟人接应 / 排时间表 / 到了先住酒店 / 什么都不扔 /
先把新家布置好）。

**用户反馈**：更希望改成**自己准备搬家或者搬宿舍**这类情况，
而不是「公司派你去」。

**处理**：把「公司要你搬」改成**中性的「你要搬」**，覆盖换工作、换学校、
搬宿舍等各种情形。要测的内核不变：

- A 靠人脉接应
- B 排流程做计划
- C 到了再说、走一步看一步
- D 什么都舍不得扔
- E 先把新家弄成家

**选项文本尽量少动**，只改那些依赖「公司派你去」这个前提的措辞
（比如「公司」相关的暗示）。轴一律不动。

## 交付与自检

改 `data/bank1.json`（s10、s18）与 `data/bank4.json`（s50）。
`id`、`next`、`goto`、`kind`、`cval` 一律不动。

自检脚本必须验证：
1. 改动只落在这 3 道题（逐字段 diff，其它题零改动）
2. id / next / goto / kind / cval 全未变
3. 每题选项数在 3~7，每选项 1~3 轴、权重 0.5~3.0
4. 同题内两两余弦 < 0.85，**报出每题最高的一对**；s50 要单独报新选项与各项的余弦
5. 选项文本无万智牌术语、同题内不重复
6. **s10 改完后，原来那五档语义仍然分得开**（逐项说明改后的措辞对应哪一档）

最后回报：逐题改动清单（旧文本 / 新文本 / 新轴 / 理由）、
自检 6 项结果、s50 需要改校验上限这件事、以及你对每条反馈处理是否恰当的说明。
