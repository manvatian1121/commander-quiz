# 新题库写作规范

你在为一款**性格测试**出题。用户做完后，我们会根据他的选择匹配一位万智牌 EDH 主将。
用户**不需要懂万智牌**——题目全部来自日常生活。

## 一、最重要的原则

**每一道题、每一个选项，都要能明确指向下面 20 个「玩法轴」中的一个或几个。**

这是唯一的硬约束。一道题如果两个选项指向的方向差不多，它就是废题。

## 二、20 个玩法轴 × 性格信号

出题时按这张表来：**先想「什么样的生活选择能暴露这个倾向」，再写题**。

## 三、出题规则

### 3.1 选项必须互不模糊（最重要的一条）

**坏例子：**
- 「你更喜欢稳定还是刺激？」—— 两个选项太抽象，谁都会想"我都想要一点"
- 「你倾向于计划还是随性？」—— 同上
- 「你喜欢和人合作吗？」—— 是/否二元，信息量太低
- A「我喜欢快一点」/ B「我不喜欢太慢」—— **两个选项是同一件事的两种说法**

**好例子：**
- 「周五晚上，朋友临时叫你去唱歌。你：」
  - A「十分钟内出门，路上再想唱什么」→ aggro / chaos
  - B「先问清楚有谁去、几点结束」→ control / politics
  - C「看情况，如果这周太累就不去了」→ 这一项**必须补一个明确的轴**，否则删掉
  - D「不去，我更喜欢按自己的节奏过」→ 需要明确指向

**每条选项都要问自己：这个选择暴露了什么倾向？** 如果你说不出来，就重写。

**禁止的选项写法：**
- 没有轴得分的中性选项（除了极少数真正的中性对照项）
- 用「看情况」「都可以」「视心情而定」当选项 —— 除非它明确对应某个轴（如 chaos）
- 同一道题里两个选项的轴组合高度重合

### 3.2 语言风格
- **不许出现万智牌术语**：不能写"主将""牌组""咒语""铺场""反击""坟场"
- 用第一人称提问也可以，用情境提问也可以
- 口语化，像朋友聊天，不要问卷腔
- 选项具体、有画面感，最好带场景细节

### 3.3 选项数量
每题 **3~5 个选项**。4 个最理想。

### 3.4 轴得分
每个选项给 1~3 个轴打 1.0~3.0 分。权重含义：
- **3.0** = 这个选项几乎就是这个轴的定义
- **2.0** = 强烈指向
- **1.5** = 明显相关
- **1.0** = 弱相关
- 不要给超过 3 个轴打分；不要出现 0.5

**注意：一个选项不能同时给方向相反的轴打高分**（例如 aggro 和 control 同时 2.5），
那说明选项本身是模糊的。

## 四、分支衍生题的格式

有些题的选项会**跳转到一道更深入的追问**，问完再回到主线。

### 数据格式
```json
{
  "id": "s08",
  "kind": "hub",
  "q": "题干",
  "opts": [
    {"t": "选项 A", "s": {"combo": 2.5}, "goto": "h1a1"},
    {"t": "选项 B", "s": {"control": 2.0}, "goto": "h1b1"},
    {"t": "选项 C", "s": {"chaos": 2.0}, "goto": "h1c1"}
  ]
}
```
分支链上的题：
```json
{"id": "h1a1", "q": "...", "opts": [...], "next": "h1a2"}
{"id": "h1a2", "q": "...", "opts": [...], "next": "h1a3"}
{"id": "h1a3", "q": "...", "opts": [...], "next": "s09"}
```

规则：
- **每道题都要有 `next` 字段**（默认下一题的 id），最后一道写 `null`
- **选项的 `goto` 优先级高于 `next`**
- 分支链最后一题用 `next` 回到主线
- 枢纽题本身在主线上，它的选项全部带 `goto`

### 分支题的要求
- 分支里的题要**顺着上一个选择往下挖**，问更具体的行为，不要换个说法问同一件事
- 分支题的轴得分要能加强或区分该分支的倾向

## 五、多选题（集中放在最后）

最后一节是 6 道多选题，格式：
```json
{"id": "s75", "multi": 3, "q": "题干", "opts": [
  {"t": "选项", "s": {"wide": 2.0}}, ...
]}
```
- `multi` 表示最多可选几个（2~4）
- 多选题题干应该是「哪些…」这类天然可多选的问题
- 多选题同样要走轴得分

## 六、自检要求

写完后必须跑脚本检查：
1. JSON 合法，每题 id 唯一
2. 每题都有 `next`（最后一道为 null）
3. 所有 `goto` 都指向存在的 id
4. 从第一题出发能走完所有主线题（不能有断链）
5. 每题选项 3~5 个，选项文本非空且**两两不同**
6. 每个选项至少有 1 个轴得分，最多 3 个
7. 权重只用 1.0 / 1.5 / 2.0 / 2.5 / 3.0
8. **模糊度检查**：同一题内任意两个选项的轴向量余弦相似度 **必须 < 0.85**，超过就重写
9. 统计 20 个轴各被多少个选项引用，每个轴至少要有 12 个选项覆盖
