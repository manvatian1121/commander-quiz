# 题库结构表（题号与跳转链已钉死，照抄不要改）

## 全局约定

- 主线共 **80 题**：`s01` ~ `s80`
- 分支衍生题共 **45 题**（5 个枢纽 × 3 条分支 × 3 题）
- 题库合计 **125 题**；一个用户实际会答 80 + 15 = **95 题**
- 每道题都要有 `next` 字段（默认下一题；最后一道 `s80` 写 `null`）
- 选项的 `goto` 优先级高于 `next`
- 每个 batch 的文件只包含**自己那部分**，不要写别人的题

## 特殊要求

### batch 5 的 s75~s80
这 6 题是**多选题**，格式为 `{"id": "s75", "multi": 3, ...}`，`multi` 取值 2~4。
题干要写成天然可多选的形式（「下面哪些…」「你会带哪几样…」）。

### 每个枢纽题（s08 / s24 / s40 / s56 / s70）
- 加 `"kind": "hub"`
- 3~4 个选项，**每个选项都必须带 `goto`**
- 枢纽题的题干要能自然地引出 3 条不同的深入方向
- 三条分支要挖不同的方向，不能是同一件事的三种问法

### 分支链（如 h1a1 → h1a2 → h1a3）
- 顺着枢纽的选择往下挖**更具体的行为**，不是换句话问同一件事
- 分支题的轴得分要**加强或细化**该分支的倾向
- 分支链最后一题 `next` 一律写 `"s09"`（对应各自的回归点）

## 输出格式

写一个 JSON 文件，结构：

```json
{
  "batch": 1,
  "questions": [
    {"id": "s01", "sec": "life", "q": "题干", "opts": [
      {"t": "选项", "s": {"aggro": 2.0}}, ...
    ], "next": "s02"},
    {"id": "s08", "sec": "life", "kind": "hub", "q": "题干", "opts": [
      {"t": "选项", "s": {"combo": 2.5}, "goto": "h1a1"}, ...
    ], "next": "s09"},
    {"id": "h1a1", "sec": "life", "q": "题干", "opts": [...], "next": "h1a2"}
  ]
}
```

`next` 的取值：
- 主线题 → 下一道主线题的 id
- 分支链中间题 → 分支链的下一题
- 分支链最后一题 → 回归点（见跳转链）
- `s80` → `null`
