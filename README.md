# EDH 主将挑选测试

> 一套生活化的性格测试，从 **489 位**当前流行的主将里，选出最合你口味的那一位。

**▶ [点这里直接玩](https://manvatian1121.github.io/commander-quiz/)**

也可以直接下载 [`commander_quiz.html`](commander_quiz.html) 双击打开——**单文件、离线、无需安装**，
发给朋友就一个文件的事。

> **完全自包含**：0 个外部脚本、0 个外部样式、0 次网络请求。断网也能用，
> 可以放在任何静态托管上，或者直接当附件发出去。

---

## 这是什么

一个纯前端的交互式测验。题目全是**生活里的小选择**，不需要你懂万智牌：

> 一群人一起玩，你最想当哪个角色？
> 老板丢给你一个完全没做过的任务，三天后要交。
> 约好了七点，对方七点二十还没到，你心里的第一反应是？

答完给你 3 位推荐主将，每位附上**一句话定位、上手难度、造价档位、这套牌在干什么、
怎么组**（含真实的搭配牌与新手指南）。

题库 144 题，**每人实际作答 105 题**——部分题目会顺着选择跳到更深入的追问，
所以每个人的路径不完全一样，但长度固定。

## 三个值得一提的设计

### 1. 开场先问接触时长，然后换一整套标准

第 1 题问「你和万智牌打过交道吗」，四个档位各自引出一条 3 题追问，
**并且切换整套评分标准**：

| 档位 | 难度容忍上限 | 流行度权重 | 强度档位上限 |
|---|---|---|---|
| 完全新人 | 1.6 | ×1.35 | Bracket 2 |
| 玩过万智牌，没打过指挥官 | 2.6 | ×1.20 | Bracket 3 |
| 打过一段时间指挥官 | 3.8 | ×1.00 | Bracket 4 |
| 老手 | 5.0 | ×0.85 | 不限 |

新人收紧难度容忍、抬高流行度权重（更容易找到攻略）、压住高强度档位；老手反过来。

实测：同一套答案只改第 1 题，新手与老手的前五推荐**重合度只有 1/5 ~ 3/5**。

### 2. 匹配的不是「你选了哪个」，而是「你和别人不一样在哪」

早期版本有个毛病：三个测试者拿到的是同一张主将。

查下来是**评分引擎的结构性缺陷**——偏好向量是 140 多道题的选项向量相加的结果，
其中「人人都一样的那部分」远大于个人口味。实测即使一个人口味非常明确，
他答出的偏好向量与别人**相似度高达 0.63**，于是推荐被少数「居中」的主将垄断。

修法是减去「平均答题者也会积累的那部分」，只留这个人与众不同的部分：

| 指标 | 修前 | 修后 |
|---|---|---|
| 不同人的偏好向量相似度 | 0.634 | **0.002** |
| 榜首过度集中程度 | 15.6× | 11.4× |

顺带发现第二个更深的问题：题库里各玩法轴的权重相差 2.15 倍，
导致**偏爱「咒语」的玩家永远拿不到咒语主将**（命中率 0.0%）。
把 641 个选项的权重按轴拉平后：

| 口味 | 修前命中率 | 修后 |
|---|---|---|
| 咒语 | **0.0%** | 38.5% |
| 闪烁 | 13.6% | 54.5% |
| 单挑 | 33.3% | 64.0% |
| **总体** | 35.2% | **42.7%** |

### 3. 主将池不是手挑的，是四条发现路径拼出来的

只用「历史累计套牌数」排名，对新主将天然不利——Reality Fracture 才发售 6 天，
累计套牌数根本追不上 2013 年的老牌。所以池子由四条路径并起来：

| 批次 | 数量 | 发现方式 |
|---|---|---|
| 一 | 100 | EDHREC 全时段排行榜 Top 100 |
| 二 | 10 | 手工补位（补齐 Top 100 覆盖薄弱的玩法方向） |
| 三 | 146 | 按**首次印刷日期**捞新主将 + 按 EDHREC「相似主将」关系爬老牌 |
| 四 | 233 | **穷举**所有能当主将的牌（含鹏洛客、载具等非生物主将），补历史 101~500 名 |

最后一批是靠 `is:commander` 穷举 1600 张能当主将的牌、逐个查真实套牌数找出来的——
一查才发现池子整段缺了历史排名 101~500 名，包括 **Dihada、Lord Windgrace、
Minsc & Boo、Aminatou** 这些鹏洛客主将。

**每位主将的档案、牌面、真实搭配牌、官方中文名全部走 API 核实，没有一条是手写的。**

## 快速开始

### 只想玩

下载 `commander_quiz.html`，双击。

### 想改代码

```bash
git clone https://github.com/manvatian1121/commander-quiz.git
cd commander-quiz
```

**改动题目**：编辑 `data/bank1..5.json`、`bankC.json`、`bankE.json`
（每个选项带 `s`（玩法轴得分）、`col`（颜色倾向）、`cval`（约束档位）），
然后跑流水线。

**改动评分**：Python 引擎在 `scripts/engine.py`，前端引擎在 `templates/quiz_template.html`。
**两边必须保持一致**，`parity_js.mjs` + `parity_compare.py` 会比对全量分数。

**重新生成**（需要联网抓数据时先跑 `data/` 里的抓取脚本）：

```powershell
# Windows PowerShell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
& .\scripts\run_all.ps1
```

```bash
# macOS / Linux（用 pwsh 或逐条执行 run_all.ps1 里的命令）
pwsh ./scripts/run_all.ps1
```

跑完会依次执行 **14 步校验**，任何一步失败都会明确报出来。

## 核心设计

### 玩法向量不是手写的

从 EDHREC 社区标签的票数换算：

```
某主将在「铺场爆兵」轴上的原始值
  = Σ (该轴相关标签的票数 / 该主将总套牌数 × 标签权重)
```

再按轴归一化（各轴 95 分位 → 3.0 满分），并设绝对下限，
防止「精准互动」这种标签支持薄弱的轴被微小数值放大成满分。

### 介绍文也不是手写的

写作素材包给每位主将提供真实牌面文字、真实流行度、以及 EDHREC 实测的
「协同度最高的牌」和「出场率最高的牌」清单。写作者**只允许提清单内的牌名**，
`validate_descriptions.py` 会逐条核查「某主将文案里提到的牌，是否真的属于它自己的清单」。

### 匹配公式

```
总分 = 0.60 × 余弦相似度
     + 0.14 × 颜色契合度
     + 0.08 × 流行度先验
     − 复杂度超限 × 0.055
     − 造价超限   × 0.050
     − 咸度超限   × 0.100
     − 强度档超限 × 0.030
```

余弦相似度用的是**减去期望值之后的偏好向量**（见上文「设计 2」）。
咸度容忍度 ≥ 4 时该项转为加分（明确想搞事的玩家，咸度是优点）。

### 难度是怎么算的

早期版本只量牌面文字长度，导致两类误判：**提示文本长的简单牌被高估**
（原初裂片妖牌面 82.8% 是括号里的规则说明，却被评成 3/5），
**牌面短但操作难的牌被低估**（大仲裁者奥古斯汀四世只有 138 字，却是锁场牌组，被评成 1/5）。

现在两项合成：

```
难度 = 0.58 × 牌面理解成本 ＋ 0.42 × 操作负担
```

**扣分用连续值，五档只是四舍五入后的显示**——否则实力相近的主将会因为跨过
一条分档线而受到差两档的惩罚。

## 已知局限

- **不是强度排名**，只匹配口味。
- **难度是估算值**，是池内的相对排名，不是绝对标准。
- **EDHREC 标签有社区偏差**：热门打法票数高，冷门但同样成立的玩法可能被淹没。
- **搭配牌来自 EDHREC 统计**，反映大众构筑习惯，不一定是最优解。
- 7 张 Final Fantasy 系列牌经 mtgch 与 Scryfall 双重确认**没有官方中文印刷**，保留英文名。
- **主将池仍在扩张中**：目前覆盖到「套牌数 ≥ 5000」，还有约 500 位（1200~5000 副）
  未纳入。加人不需要改代码，跑一遍发现脚本 + 写作流程即可。

## 贡献

欢迎提 Issue 和 PR。几个特别欢迎的方向：

- **题库**：题目、选项、玩法轴得分都在 `data/bank*.json` 里，纯 JSON 好改
- **主将池**：跑 `scripts/` 里的发现脚本就能扩充，瓶颈只在介绍文的写作
- **评分口径**：如果你觉得某类玩法被系统性低估，`axis_validation.py` 的能量化验证
- **英文版**：目前全中文，翻译工作量主要在题库与 489 篇介绍文

改完请务必跑 `scripts/run_all.ps1`——14 步校验会挡住绝大多数回归。
